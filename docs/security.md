# セキュリティ対策

## 方針

- 実施できる対策は実施します。ただし、**追加の設定なしで `docker run` だけで起動できること**は維持します。
  そのため、利用環境に依存する対策(認証のトークン、受け付けるホスト名など)は、環境変数で有効にする方式にしています。
- 映像・音声は個人情報(顔・声・車のナンバーなど)を含み得ます。**信頼できるネットワークの外に公開する場合は、必ず `API_TOKEN` を設定し、TLS(HTTPS)を終端するリバースプロキシの内側に置いてください。**
- 方針の詳細は `AGENTS.md` の第 2 節を参照してください。

## 実施している対策

| 対策 | 既定 | 設定 | 内容 |
|---|---|---|---|
| トークン認証 | 無効 | `API_TOKEN` | 設定すると `/api/*`、`/compute/*`、`/mcp`(MCP サーバー)にトークンが必要になります(下記) |
| 取り込めるフォルダの制限 | 有効 | `INGEST_ROOTS` | パス指定・フォルダ一括で取り込めるのは、既定で `/recordings` と `DATA_DIR` の下だけです。監視フォルダ(`WATCH_DIRS`)は自動で許可されます。シンボリックリンクと `..` は解決してから判定します |
| 取り込むファイルの検証 | 有効 | なし | 拡張子が映像・音声で、ffprobe で読めるものだけを受け付けます。取り込みに失敗したものや、許可したフォルダの外のものは配信しません |
| CSRF の防止 | 有効 | `ALLOWED_ORIGINS` | 更新系のリクエスト(POST など)は、別のサイトのページから送られたもの(Origin / Sec-Fetch-Site で判定)を 403 で拒否します。curl などブラウザ以外からの利用には影響しません |
| Host ヘッダーの確認 | 無効 | `ALLOWED_HOSTS` | 受け付けるホスト名を限定し、DNS リバインディングを防ぎます(例: `search.local,192.168.1.20`) |
| リクエストの大きさの上限 | 4096 MB | `MAX_UPLOAD_MB` | これを超えるアップロードは 413 で拒否します(`0` で無制限) |
| 応答ヘッダー | 有効 | なし | `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、WebUI に CSP |
| 一般ユーザーでの実行 | 有効 | `PUID` / `PGID` | 起動直後にデータ置き場の所有者を整え、uid / gid 1000 の一般ユーザーに切り替えて動かします。`PUID=0` で root のまま動かせます |
| 依存物の固定 | 有効 | なし | transformers のアーカイブをハッシュで照合し、モデルの版(Hugging Face のコミット)を固定しています |
| 脆弱性の検査 | 有効 | なし | リリースごとと毎週、全イメージの SBOM を作り、既知の脆弱性を検査します(`docs/release.md`) |

## トークン認証の使い方

```bash
# 推測されにくいトークンを作る(32 文字以上を推奨)
TOKEN=$(python3 -c "import secrets; print(secrets.token_urlsafe(32))")

docker run -d -p 8000:8000 -v ./data:/data -e API_TOKEN="$TOKEN" ghcr.io/miyabiver39/embeddinggemma-poc:cpu

curl -H "Authorization: Bearer $TOKEN" localhost:8000/api/info
```

- ヘッダーは `Authorization: Bearer <トークン>` か `X-API-Key: <トークン>` のどちらでも構いません。
- WebUI は、最初の操作時にトークンの入力を求め、ブラウザに 30 日間保存します(Cookie、`SameSite=Strict`)。「状態」タブで消去できます。
- 認証なしで開けるのは `/healthz`(死活監視)、`/`(WebUI の画面)、`/docs`・`/redoc`・`/scalar`(API 仕様の画面)、`/openapi.json`(仕様書。リポジトリでも公開している内容)だけです。データの取得(`/api`・`/compute`・`/mcp`)にはトークンが必要です。
- app と compute を分ける構成では、compute に `API_TOKEN` を、app に同じ値の `EMBEDDING_TOKEN` を設定します
  (app 自身にも `API_TOKEN` を設定する場合、`EMBEDDING_TOKEN` を省略すると同じ値を使います)。

## 一般ユーザーでの実行と、ファイルの権限

- 録画フォルダ(`/recordings`)のファイルは、uid 1000 の利用者が読める必要があります。読めない場合は、ホストの所有者に合わせて
  `-e PUID=<uid> -e PGID=<gid>` を指定するか、ファイルに読み取り権限を付けてください。
- `DATA_DIR` の所有者は起動時に自動で合わせます。以前の版(root で動いていた版)で作ったデータも、そのまま引き継げます。
- GPU のデバイスファイル(`/dev/dri`、`/dev/kfd`)のグループは自動で引き継ぎます。NVIDIA(`--gpus`)は追加の設定は不要です。
  GPU の実機での確認はまだです。GPU が使われない場合は `docs/gpu.md` を参照し、切り分けのために `-e PUID=0` も試してください。

## 残っているリスクと、利用者側の対策

| リスク | 内容 | 対策 |
|---|---|---|
| 通信の暗号化 | アプリ自体は HTTP のみです(トークンも平文で流れます) | 外部に出す場合は、TLS を終端するリバースプロキシ(nginx、Caddy など)の内側に置く |
| 既定では認証なし | 追加の設定なしで起動できるようにするため、`API_TOKEN` の既定は空です。起動時に警告を出します | 信頼できるネットワークの外で使う場合は `API_TOKEN` を設定する |
| ffmpeg の脆弱性 | Ubuntu の ffmpeg は universe 区画のパッケージで、修正の提供が遅れがちです(検査結果の Medium の大半) | 出どころの分からない映像は取り込まない。一般ユーザーでの実行により、影響を受けてもコンテナ内の権限は限定される |
| WebUI のトークンの保存 | WebUI は表示にスクリプトを使うため、Cookie を JavaScript から読める形で保存しています | 共用の端末では、使用後に「状態」タブでトークンを消去する |
| GitHub Actions の固定 | Actions はタグ(`@v4` など)で指定しており、コミットのハッシュでは固定していません | Dependabot の更新提案を確認して取り込む |
| 監視フォルダ・録画フォルダの中身 | 許可したフォルダの中にある映像・音声は、誰でも(トークンを持つ人は)取得できます | 取り込む必要のあるフォルダだけを読み取り専用(`:ro`)でマウントする |
