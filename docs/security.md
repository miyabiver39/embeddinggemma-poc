# セキュリティ対策

## 方針

- 実施できる対策は実施します。ただし、**追加の設定なしで `docker run` だけで起動できること**は維持します。
  そのため、利用環境に依存する対策(認証のトークン、受け付けるホスト名など)は、環境変数で有効にする方式にしています。
- 映像・音声は個人情報(顔・声・車のナンバーなど)を含み得ます。**信頼できるネットワークの外に公開する場合は、必ず `API_TOKEN` を設定し、TLS(HTTPS)を終端するリバースプロキシの内側に置いてください。**
- 方針の詳細は `AGENTS.md` の第 2 節を参照してください。

## 実施している対策

| 対策 | 既定 | 設定 | 内容 |
|---|---|---|---|
| トークン認証 | 無効 | `API_TOKEN` | 設定すると `/api/*`、`/compute/*`、`/mcp`(MCP サーバー)にトークンが必要になります(下記) |
| 取り込めるフォルダの制限 | 有効 | `INGEST_ROOTS` | パス指定・フォルダ一括で取り込めるのは、既定で `/recordings` と `DATA_DIR` の下だけです。監視フォルダ(`WATCH_DIRS`)は自動で許可されます。シンボリックリンクと `..` は解決してから判定します |
| 取り込むファイルの検証 | 有効 | なし | 拡張子が映像・音声・画像・文書で、ffprobe(画像は Pillow、文書は形式の確認)で読めるものだけを受け付けます。取り込みに失敗したものや、許可したフォルダの外のものは配信しません |
| 文書の読み込みの上限 | 有効 | なし | 文書は信頼できないファイルとして扱い、テキストは 32MB、Word の本文は展開後 64MB、PDF は 5000 ページ、取り出す文字は 200 万字までに限ります(zip 爆弾や巨大な PDF で、メモリと時間を使い切らないため)。元の文書は、ブラウザで開かずダウンロードとして返します(`Content-Disposition: attachment`) |
| 読み取り専用のトークン | 無効 | `API_READ_TOKEN` | 検索・参照(GET と検索の POST)だけを許可します。取り込み・変更・削除は 403。MCP では取り込みのツールを拒否します。`API_TOKEN` を設定したときだけ有効です |
| 検索の同時実行の上限 | 32 件 | `MAX_PENDING_SEARCHES` | 上限を超えた検索は 503 で断ります(大量の検索で、推論の順番待ちと API のスレッドが詰まるのを防ぐ) |
| 通知ルールの送り先 | 有効 | なし | 通知ルール(Webhook)の作成・変更は `API_TOKEN` でだけできます(読み取り専用のトークンでは不可)。送り先は `http` / `https` の URL だけを受け付け、転送(リダイレクト)には従いません。本文には HMAC-SHA256 の署名を付けます(`docs/api.md` の 8.)。鍵は作成時の応答にだけ含め、一覧などでは返しません |
| バックアップ | 有効 | `BACKUP_DIR` | `POST /api/admin/backup` は `API_TOKEN` でだけ実行できます(読み取り専用のトークンでは不可)。同時に 2 つは作らず(409)、保存先の空き容量が足りなければ取りません(507)。バックアップには DB(取り込み元のパス・通知ルールの鍵を含む)が入るため、保存先の権限を絞ってください |
| 監視の値 | 有効 | なし | `GET /metrics` は `/api` と同じく認証が要ります。HTTP の要求の数は経路のひな形ごとに数え、任意のパス・メソッドを送られても値の種類が増えないようにしています |
| CSRF の防止 | 有効 | `ALLOWED_ORIGINS` | 更新系のリクエスト(POST など)は、別のサイトのページから送られたもの(Origin / Sec-Fetch-Site で判定)を 403 で拒否します。curl などブラウザ以外からの利用には影響しません |
| Host ヘッダーの確認 | 無効 | `ALLOWED_HOSTS` | 受け付けるホスト名を限定し、DNS リバインディングを防ぎます(例: `search.local,192.168.1.20`)。`localhost`・`127.0.0.1`・`::1` は、コンテナの死活監視のため常に許可します(DNS リバインディングでは攻撃者のドメイン名が Host に入るため、許可しても防げます) |
| 切り出しの制限 | 600 秒 | `CLIP_MAX_SEC` | `GET /api/sources/{id}/clip` は `/api/media` と同じ条件(認証・許可したフォルダの中・検証済み・保存する設定)のものだけを切り出します。長さの上限を設け、同時に 2 件までに限ります(ffmpeg の負荷で取り込みを止めないため)。`0` で無効 |
| リクエストの大きさの上限 | 4096 MB | `MAX_UPLOAD_MB` | これを超えるアップロードは 413 で拒否します(`0` で無制限) |
| 応答ヘッダー | 有効 | なし | `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、WebUI に CSP |
| 一般ユーザーでの実行 | 有効 | `PUID` / `PGID` | 起動直後にデータ置き場の所有者を整え、uid / gid 1000 の一般ユーザーに切り替えて動かします。`PUID=0` で root のまま動かせます |
| ストリームの URL の扱い | 有効 | `MAX_STREAMS` | RTSP の URL は `rtsp://` / `rtsps://` だけを受け付け、ffmpeg が使えるプロトコルを RTSP 関連(TCP / UDP / TLS / RTP)に限ります(ローカルのファイルなどは読ませません)。URL のパスワードは、API の応答・エラー・ログで `***` に伏せます |
| 依存物の固定 | 有効 | なし | transformers のアーカイブをハッシュで照合し、モデルの版(Hugging Face のコミット)を固定しています。ベースイメージ(Ubuntu 24.04)は内容のハッシュ(digest)で固定しています |
| 認証なしの応答の情報 | 有効 | なし | `/readyz` は認証なしで開けるため、失敗の理由は例外の種類だけを返し、文言(パス・接続先などを含み得る)はサーバーのログにだけ残します |
| ファイルの有無の秘匿 | 有効 | なし | パス指定の取り込みは、ファイルの有無より先に、許可したフォルダの中かを確かめます。外のパスは、ファイルの有無にかかわらず 403 を返します(許可していない場所のファイルを探れないようにするため) |
| ブランチの保護 | 有効 | なし | main への変更はプルリクエストだけで受け付け、CI のテスト(`test`)の成功を必須にしています。強制 push と削除は禁止です。Dependabot の脆弱性の通知と、自動の修正提案も有効にしています |
| CI の供給網の対策 | 有効 | なし | GitHub Actions の Action はコミットのハッシュで固定し、版をコメントで示します(Dependabot が更新を提案)。ワークフローの権限は既定で読み取りだけにし、書き込みはそれが要るジョブ(バッジの更新・イメージの公開・リリースへの添付)にだけ与えます。プルリクエストのコードを動かすテストのジョブには書き込みの権限を持たせません。脆弱性検査のツールのインストーラは、コミットとハッシュで固定します |
| 脆弱性の検査 | 有効 | なし | リリースごとと毎週、全イメージの SBOM を作り、既知の脆弱性を検査します(`docs/release.md`) |

## トークン認証の使い方

```bash
# 推測されにくいトークンを作る(32 文字以上を推奨)
TOKEN=$(python3 -c "import secrets; print(secrets.token_urlsafe(32))")

docker run -d -p 8000:8000 -v ./data:/data -e API_TOKEN="$TOKEN" ghcr.io/miyabiver39/embeddinggemma-poc:cpu

curl -H "Authorization: Bearer $TOKEN" localhost:8000/api/info
```

- ヘッダーは `Authorization: Bearer <トークン>` か `X-API-Key: <トークン>` のどちらでも構いません。
- WebUI は、最初の操作時にトークンの入力を求め、ブラウザに 30 日間保存します(Cookie、`SameSite=Strict`)。「状態」タブで消去できます。
- 認証なしで開けるのは `/healthz`(死活監視)、`/`(WebUI の画面)、`/docs`・`/redoc`・`/scalar`(API 仕様の画面)、`/openapi.json`(仕様書。リポジトリでも公開している内容)だけです。データの取得(`/api`・`/compute`・`/mcp`)にはトークンが必要です。
- app と compute を分ける構成では、compute に `API_TOKEN` を、app に同じ値の `EMBEDDING_TOKEN` を設定します
  (app 自身にも `API_TOKEN` を設定する場合、`EMBEDDING_TOKEN` を省略すると同じ値を使います)。

## 一般ユーザーでの実行と、ファイルの権限

- 録画フォルダ(`/recordings`)のファイルは、uid 1000 の利用者が読める必要があります。読めない場合は、ホストの所有者に合わせて
  `-e PUID=<uid> -e PGID=<gid>` を指定するか、ファイルに読み取り権限を付けてください。
- `DATA_DIR` の所有者は起動時に自動で合わせます。以前の版(root で動いていた版)で作ったデータも、そのまま引き継げます。
- GPU のデバイスファイル(`/dev/dri`、`/dev/kfd`)のグループは自動で引き継ぎます。NVIDIA(`--gpus`)は追加の設定は不要です。
  GPU の実機での確認はまだです。GPU が使われない場合は `docs/gpu.md` を参照し、切り分けのために `-e PUID=0` も試してください。

## 残っているリスクと、利用者側の対策

| リスク | 内容 | 対策 |
|---|---|---|
| 通信の暗号化 | アプリ自体は HTTP のみです(トークンも平文で流れます) | 外部に出す場合は、TLS を終端するリバースプロキシの内側に置く。Nginx の設定は `deploy/` に用意しています([docs/nginx.md](nginx.md)) |
| 既定では認証なし | 追加の設定なしで起動できるようにするため、`API_TOKEN` の既定は空です。起動時に警告を出します | 信頼できるネットワークの外で使う場合は `API_TOKEN` を設定する |
| ffmpeg の脆弱性 | Ubuntu の ffmpeg は universe 区画のパッケージで、修正の提供が遅れがちです(検査結果の Medium の大半) | 出どころの分からない映像は取り込まない。一般ユーザーでの実行により、影響を受けてもコンテナ内の権限は限定される |
| WebUI のトークンの保存 | WebUI は表示にスクリプトを使うため、Cookie を JavaScript から読める形で保存しています | 共用の端末では、使用後に「状態」タブでトークンを消去する |
| Python の依存のハッシュ照合 | PyTorch などの Python の依存は版を固定していますが、配布物のハッシュまでは照合していません(transformers を除く) | 公開されたイメージの SBOM と脆弱性検査の結果で、入っている版を確認する。下記「受け入れなかった指摘」 |
| ストリームの認証情報の保存 | RTSP の URL(パスワードを含む)は、再起動後に接続し直すため、DB(`mediasearch.db`)に平文で保存します | `DATA_DIR` を他の利用者が読めない場所に置く。カメラには閲覧専用のアカウントを使う |
| ストリームの接続先 | トークンを持つ人は、任意のホストの RTSP に、サーバーから接続させられます | `API_TOKEN` を設定する。サーバーの通信先をファイアウォールで限定する |
| `cuda` イメージの C コンパイラ | 推論の高速化(torch.compile)のため、`cuda` イメージには gcc が入っています。コンテナに侵入された場合に、攻撃者がコンパイラを使える状態です | 一般ユーザーでの実行により、権限はコンテナ内の一般ユーザーに限られます。`compile` の結果は `DATA_DIR/cache/torch` に保存されるため、`DATA_DIR` を他の利用者が書き込めない場所に置く |
| 監視フォルダ・録画フォルダの中身 | 許可したフォルダの中にある映像・音声は、誰でも(トークンを持つ人は)取得できます | 取り込む必要のあるフォルダだけを読み取り専用(`:ro`)でマウントする |

## コードの検査(Code scanning)の指摘の扱い

GitHub の Security タブには、CodeQL(ソースコードの静的解析)と OpenSSF Scorecard(OSS としての取り組みの点数)の指摘が表示されます。
指摘は 1 件ずつ確認し、直すものと、直さないもの(理由を付けて GitHub 上で却下)に分けています。2026-11-20 の判断は次のとおりです。

### 直したもの

| 指摘 | 内容 | 対応 |
|---|---|---|
| CodeQL `py/path-injection`(`api.py` のパス指定の取り込み) | ファイルの有無を、許可したフォルダの確認より先に調べていた。400(無い)と 403(外)の違いから、許可していない場所のファイルの有無を調べられた | 許可したフォルダの確認を先に行う |
| CodeQL `py/stack-trace-exposure`(`main.py` / `service.py` の `/readyz`) | 認証なしの `/readyz` が、例外の文言(パスや接続先を含み得る)を返していた | 例外の種類だけを返し、詳細はログに残す |
| CodeQL `actions/unpinned-tag`、Scorecard `Pinned-Dependencies`(ワークフロー) | Action をタグで指定していた。インストーラを main ブランチから取得していた | コミットのハッシュで固定。インストーラはハッシュも照合 |
| Scorecard `Pinned-Dependencies`(Dockerfile の `FROM`) | ベースイメージをタグで指定していた | digest で固定。Dependabot は Ubuntu 24.04 の中の更新だけを提案する |
| Scorecard `Branch-Protection` | main のブランチ保護が無かった | main を保護した(プルリクエストを必須にし、直接の push・強制 push・削除を禁止。`build.yml` の `test` の成功を必須。管理者にも適用) |
| Scorecard `Security-Policy` | `SECURITY.md` に、報告先の URL が書かれていなかった | 非公開の報告の画面の URL を追記 |
| Scorecard `Token-Permissions`(`build.yml`) | ワークフロー全体の既定の権限が無く、テストのジョブに書き込みの権限があった | 既定を読み取りだけにし、バッジの書き込みを別のジョブに分けた |

### 受け入れなかった指摘(理由)

| 指摘 | 理由 |
|---|---|
| CodeQL `py/stack-trace-exposure`(`api.py` の `/api/info`) | 応答に入るのは、アプリが作った接続の失敗の説明(compute の URL と、確認すべき設定)で、スタックトレースではありません。認証が要る経路で、運用者が原因を調べるための情報のため、そのまま返します |
| CodeQL `py/stack-trace-exposure`(`api.py` の画像の取り込み) | 応答に入るのは、アプリが作った検証の説明(読めない画像の名前と理由)です。利用者が送ったファイルのどれが、なぜ取り込めなかったかを返すための情報のため、そのまま返します |
| Scorecard `Pinned-Dependencies`(Dockerfile の `pip install`) | PyTorch はバリアント(cpu / cu126 / rocm / xpu)ごとに配布元と配布物が違い、ハッシュの一覧を保てる仕組みが現時点でありません。版は固定し、transformers はハッシュで照合しています。入っている版は SBOM で確認できます |
| Scorecard `Token-Permissions`(`security.yml` の report、`build.yml` の security と badges) | リリースへの添付と badges ブランチの更新に `contents: write` が必要です。書き込みはこれらのジョブだけに限っています |
| Scorecard `Code-Review` | 保守者が 1 人のため、他者のレビューの承認は必須にしていません(自分のプルリクエストを自分で承認できないため)。複数人で保守するときは、承認の必須化を推奨します |
| Scorecard `Maintained` / `CI-Tests` / `SAST` | 作成から日が浅いこと、過去の変更の実績から計算される項目で、運用を続けると改善します(CI のテストと CodeQL は実施しています) |
| Scorecard `Fuzzing` / `CII-Best-Practices` | 検証用途の範囲では、ファジングの導入と OpenSSF のベストプラクティスの登録は行いません |
